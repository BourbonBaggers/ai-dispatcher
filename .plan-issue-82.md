# Issue #82: Add an interactive-ownership label that durably excludes an issue from dispatcher intake

## Goal
Add a first-class hold label (`interactive`) that durably keeps an issue out of dispatcher
intake — excluded from selection, immune to intake-label migration re-deriving
`dispatch:ready`, untouched by the blocked-queue audit, and never added or removed by the
dispatcher itself — replacing the currently-insufficient advice to just avoid adding
dispatcher labels.

## Root cause (from the issue)
- `HOLD_LABELS` in `src/labels.ts` only contains `needs-input`, `blocked`,
  `autoship-held`. `blocked` alone is not durable: the blocked-queue audit
  (`src/blocked-queue.ts`) treats a `blocked`-only issue as a candidate to
  auto-unblock, and unblocking re-adds `dispatch:ready` via
  `migrateIntakeLabels` (`src/dispatcher.ts`), re-deriving admission from ordinary
  `type:*`/`risk:*`/`priority:*` labels that `AGENTS.md` says are safe.
- There is no label that is (a) in `HOLD_LABELS` so selection excludes it and
  migration is suppressed for it, and (b) never itself touched by the audit's
  stale-`blocked` removal, and (c) never added/removed by any dispatcher code path.
