# Issue #101: Lockfile-keyed dependency reuse

## Goal
Avoid a fresh `npm ci` for every checkout while keeping generated and agent-written
dependencies private to each run. Cache entries are keyed by lockfile, Node major, and
optional Prisma schema; incomplete entries are never published.

## Milestone 1: Cache key, storage, and safe attachment
- Add a dependency-cache helper with a deterministic key, repository-scoped cache
  location, completion marker, serialized installation, and private attachment.
- Include `db:generate` in cache population when defined by the target package.
- Cover cache hits, misses, corrupt entries, concurrent misses, and schema changes.
- Commit as `milestone(1): ...`.

## Milestone 2: Launcher integration and changed-lockfile handling
- Pass the configured state directory to the launcher and call the cache helper before
  an agent launch. Detect a changed key on subsequent launches; use a private install
  for that checkout and report the reason.
- A cache or attach failure must log its reason and use private `npm ci`.
- Emit one timing and outcome event per launch.
- Cover launcher wiring and lockfile edits; commit as `milestone(2): ...`.

## Milestone 3: Pruning, documentation, and final verification
- Retain only a bounded number of recent keys per repository without touching an
  entry being populated or used. Cover pruning.
- Document the cache path, override, isolation, fallback, and housekeeping.
- Run `npm test`, `npm run typecheck`, and `scripts/shellcheck-ci.sh`.
- Commit as `milestone(3): ...`, push, and open a ready-for-review PR with `Issue: #101`.
