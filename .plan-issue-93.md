# Issue #93: Keep deploy recovery anchored to the merged delivery

## Goal
Prevent a failed deploy after merge from spawning a replacement PR or a false
operator hold. Preserve the original merged PR as delivery evidence and make
recovery and exhaustion reports reflect what actually happened.

## [DONE] Milestone 1: Preserve merged delivery and complete it when production contains it
- Record and retain the merged PR and SHA through later recovery observations.
- Recheck that delivery before any hold and during held rechecks; complete a run
  when the merged commit is verified in production.
- Add regression tests for a second PR observation and an already delivered merge.
- Commit as `milestone(1): ...`.

## [DONE] Milestone 2: Keep infrastructure and unpublished-work failures out of agent exhaustion
- Retry a merged PR's environmental or connectivity deploy failure with bounded
  backoff, without launching a code agent.
- Treat launcher-synthesized exit 75 as recoverable unpublished work, without
  spending the frontier exhaustion budget.
- Add focused tests for both paths.
- Commit as `milestone(2): ...`.

## Milestone 3: Make exhaustion evidence truthful and provide supported release
- Report the actual attempted models and require a real frontier attempt before
  recording exhaustion.
- Add a supported `release --issue N [--pr M]` operation for an exhausted claim.
- Update command documentation and tests; run the full test and typecheck suites.
- Commit as `milestone(3): ...`.
